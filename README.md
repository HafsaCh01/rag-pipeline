## Week 2: Chunking, Embeddings & Vector DB

### Overview
This week builds on the cleaned dataset (`data/clean_dataset.csv`) from Week 1 to implement chunking, generate embeddings, store them in ChromaDB, and benchmark retrieval performance.

### Approach

**Chunking strategy: Recursive character splitting**
Text is split using a prioritized list of separators — paragraph breaks, then line breaks, then sentence boundaries, then spaces, then hard character cuts as a last resort. The splitter tries the largest boundary first and only falls back to smaller ones if a piece is still too big. This keeps chunks aligned to natural text boundaries instead of cutting mid-sentence.

- Chunk size: 500 characters
- Chunk overlap: 50 characters
- Implementation: `scripts/chunk_text.py`
- Tests: `tests/test_chunking.py` (14 unit tests covering empty input, short/long text, overlap behavior, invalid params, and edge cases like a single very long word)

**Embeddings**
Generated using `sentence-transformers` with the `all-MiniLM-L6-v2` model. Embedding time and per-chunk latency are logged to `reports/embedding_performance.json`.

- Script: `scripts/generate_embeddings.py`
- Output: `data/embeddings.npy`, `data/chunks_meta.json`

**Vector database: ChromaDB**
Chunks and embeddings are ingested into a persistent ChromaDB collection (`ag_news_chunks`) stored at `data/chroma_db`. Ingestion is batched (500 items/batch) to handle large datasets, and the script skips re-ingesting if the collection is already populated.

- Script: `scripts/setup_chromadb.py`

**Retrieval benchmarking**
Semantic search is tested against 5 sample queries spanning different news categories. Latency per query and summary stats (avg/min/max/median) are logged.

- Script: `scripts/test_retrieval.py`
- Output: `reports/retrieval_latency.json`

### Edge Cases Handled
- Empty or whitespace-only text produces no chunks
- `chunk_overlap >= chunk_size` raises a `ValueError`
- A single word longer than `chunk_size` is hard-split by character
- Mismatched embeddings/metadata counts raise an error before ingestion
- Re-running ingestion on an already-populated collection is a no-op

## Week 3: LLM Integration & Prompt Engineering

### Overview
This week wires the Week 2 retrieval pipeline (ChromaDB + sentence-transformers) to an LLM via OpenRouter, adding prompt engineering, robust error handling, hallucination detection, and out-of-domain query handling.

### Approach

**LLM Integration**
Answers are generated by calling OpenRouter's chat completions endpoint. The system prompt instructs the model to answer strictly from retrieved context and to explicitly refuse when context is insufficient, rather than filling gaps with outside knowledge.

- Script: `scripts/llm_integration.py`
- Model: configurable via `MODEL` constant; currently set to `openrouter/free` (OpenRouter's auto-router), since individual free-tier model IDs on OpenRouter rotate out frequently. Swappable to a paid model like `deepseek/deepseek-chat` if credits are available.

**Prompt Engineering**
- System prompt fixes the assistant's role, enforces context-only answering, and defines an exact refusal phrase for insufficient-context cases.
- User prompt injects retrieved chunks labeled with `chunk_id`, followed by the question, so the model can cite sources.
- Temperature set low (0.1) to reduce creative drift and hallucination.

**Error Handling**
`call_llm()` handles:
- Missing API key → raises immediately with a clear fix instruction
- 401/403 (auth errors) → raises immediately, no wasted retries
- 429 (rate limited) → exponential backoff retry
- 5xx (server errors) → exponential backoff retry
- Timeouts and connection errors → retried with backoff
- All other unexpected statuses → captured and returned as an error field, no crash
- Some free-tier models return their answer in a `reasoning` field instead of `content`; the code falls back to `reasoning` when `content` is empty

**Hallucination Checks**
`check_hallucination_risk()` is a lightweight heuristic that flags answers with very low vocabulary overlap against the retrieved context — a signal (not proof) that the model may have answered from outside knowledge instead of the provided chunks. Correct refusals are never flagged.

**Out-of-Domain Handling**
`is_query_in_domain()` checks whether any chunks were retrieved at all, and optionally whether the best match distance exceeds a threshold. Queries with no relevant matches (e.g. asking about Olympic curling against an AG News dataset) are short-circuited before an LLM call is even made, returning a fixed "out of scope" message.

**Latency Logging**
`run_rag_pipeline.py` wires retrieval + generation end-to-end, logging retrieval latency, generation latency, and total latency per query to `reports/e2e_latency.json`.

- Script: `scripts/run_rag_pipeline.py`
- Output: `reports/e2e_latency.json`

### Files
- `scripts/llm_integration.py` — LLM calling, prompt building, hallucination check, domain check
- `scripts/run_rag_pipeline.py` — end-to-end pipeline wiring retrieval + generation + logging
- `tests/test_llm_integration.py` — 19 unit tests (mocked API calls, no real network/cost)

### Edge Cases Handled
- No API key set → clear error instead of a raw exception
- Rate limits (429) → automatic retry with exponential backoff
- Auth failures (401/403) → fail fast, no wasted retry attempts
- Server errors (5xx) and network timeouts → retried before giving up
- Zero chunks retrieved → treated as out-of-domain, no LLM call made
- Model returns answer in `reasoning` instead of `content` → handled via fallback
- Model correctly refuses due to insufficient context → not flagged as hallucination

## How to Run This Project

```bash
git clone <your-repo-url>
cd rag-pipeline
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Set your OpenRouter API key (get one free at openrouter.ai)
setx OPENROUTER_API_KEY "your-key-here"     # Windows PowerShell — restart terminal after

# Week 1: data acquisition and cleaning
python scripts/verify_setup.py
python scripts/build_raw_dataset.py
python scripts/validate_dataset.py
pytest tests/test_clean_text.py -v
python scripts/run_pipeline.py

# Week 2: chunking, embeddings, vector DB, retrieval
python scripts/generate_embeddings.py
python scripts/setup_chromadb.py
python scripts/test_retrieval.py
pytest tests/test_chunking.py -v

# Week 3: LLM integration, end-to-end pipeline
python scripts/run_rag_pipeline.py
pytest tests/test_llm_integration.py -v
```
